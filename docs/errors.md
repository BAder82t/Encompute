# Encompute error codes

Every diagnostic carries a stable code. The CLI prints `error[CODE]: message`;
Python raises `encompute.EncomputeError` with `.code` and `.message`.

| Code | Raised by | Meaning | What to do |
|---|---|---|---|
| ENC1001 | Python frontend | Python control flow on a secret (`if`, `while`, `and`/`or`/`not`, `bool()`, builtin `min`/`max`) | Use `encompute.select(cond, a, b)`, `& \| ~`, or `encompute.minimum`/`maximum` on exact values; express approximate logic arithmetically |
| ENC1002 | Python frontend | Division by a secret value | Divide by public values only |
| ENC1003 | Python frontend | Comparison (or logic, shift) on approximate (float) secrets | Declare the inputs with exact types (`secret[u32, lo:hi]`, `secret[bool_]`); comparisons of exact values give encrypted Booleans |
| ENC1004 | Python frontend | A secret flows into a public sink (`print`, `str`, f-string, `float`, `int`, logging) | Return the value as an output; the client decrypts it |
| ENC1005 | frontend, IR | Operation not supported on secrets (indexing, iteration, non-integer powers, secret matrices, `select` without an encrypted bool condition, programs mixing approximate and exact values) | See the message for the version that adds it |
| ENC1101 | frontend, IR | Secret input has no declared range, or `lo >= hi` | `secret[float, lo:hi]` / `secret[Tensor[n], lo:hi]` |
| ENC1102 | runtime, control plane | Input missing, wrong length, unknown, or outside its declared range. On the control plane: a malformed request, including a query string that names a parameter twice, or a service account asked to hold `security_admin` | Fix the input; ranges are part of the security and precision contract. Give `security_admin` to people only |
| ENC1201 | compiler | Multiplicative depth exceeds the largest 128-bit parameter set (N = 2^16) without bootstrapping | Reduce chained multiplications or approximation degree. CKKS bootstrapping is not supported yet |
| ENC1202 | compiler | Precision unreachable: scale above 59 bits, first modulus above 60 bits, unbounded range, or a sigmoid needing degree > 127 | Relax `precision` or narrow input ranges |
| ENC1301 | frontend, IR | Type error: shape mismatch, public-only computation, output not depending on a secret, bad constant | See message |
| ENC1302 | IR parser | Malformed `.eir` text (message includes the line) | — |
| ENC1303 | analysis | An exact integer operation may overflow its type for inputs in the declared ranges, a lookup index may leave its table, or an exact output may exceed ±2^53 | Use a wider type (`cast`) or narrower input ranges |
| ENC1401 | runtime | Artifact missing, modified (hash mismatch), or compiled by a different Encompute version | Recompile the artifact |
| ENC1501 | backend | Backend error (OpenFHE exception, missing rotation key, depth budget exhausted, build without OpenFHE); an operation outside the exact backend's capability matrix (for example a lookup table over 256 entries); BACKEND UNAVAILABLE: TFHE-rs requested in a production build; a decrypted exact output outside the range analysis proved for it ("outside its proven range ... the result is wrong"): the client refuses to return it | See message; for TFHE-rs, use OpenFHE exact (the default). Never use an output refused as outside its proven range; report the evaluator |
| ENC1601 | envelope | Malformed, truncated or corrupted envelope (checksum mismatch) | — |
| ENC1602 | envelope | Wrong kind, format, scheme or backend version | Match client and evaluator versions |
| ENC1603 | envelope | Made for a different parameter set | Recompile or regenerate keys |
| ENC1604 | envelope, evaluator | Made for a different program; or an uploaded program compiles to another ID than the job grant names | — |
| ENC1605 | envelope | Different or unregistered key | Upload `eval.keys` |
| ENC1606 | client | An execution receipt is malformed, has a bad signature, comes from an untrusted evaluator key, or does not match the program, plan, parameters, key, request or response | Do not use the result; check which evaluator you trust (`--trust-evaluator`) and that request and response were not altered |
| ENC1701 | remote | Network or protocol failure between client and evaluator | — |
| ENC1702 | client, audit | A semantic transcript is malformed, of an unknown version, or its hash does not match the exact plan or the verification metadata ("transcript commitment mismatch") | Recompile the artifact; do not trust a receipt whose transcript hash differs |
| ENC1801 | compiler, client | Verified execution was required but is not possible or failed: the program uses an operation or type no proof backend covers, the evaluator sent no proof, or the proof does not verify; on the BGV profile, a program whose worst-case noise exceeds the calibrated budget ("cannot be verified on the BGV profile") | Use `verification="receipt"`, restrict the program to the proven subset, or refuse the result; never decrypt without a valid proof when verification is required |
| ENC1901 | compiler | A confidential value flows to a public output | Keep it sealed, or derive a public value only where every source asset allows it |
| ENC1902 | compiler | A value is revealed to a party that may not learn it (outside its audience, or release `never`) | Reveal only to parties every source asset allows |
| ENC1903 | compiler | An input asset does not allow the program's purpose (or the program declares none) | Declare a purpose every input asset allows |
| ENC1904 | compiler | A derivation weakens a policy more than its source assets permit | Ask the owners to permit that derivation (`derive [...]`), or keep it restricted |
| ENC1905 | compiler | An aggregate-only value (e.g. a gradient) is revealed without an aggregation boundary | Keep it sealed until it is aggregated |
| ENC1906 | compiler | Confidentiality declarations are malformed: unknown party or asset, duplicate IDs, unbound secret input, bad ID or release | Fix the declaration |
| ENC2001 | broker, verifier | Attestation evidence is malformed, forged or tampered, from an unknown provider or signing key, or does not commit to the workload binding it was sent with (a substituted session key, evaluator key, spec or policy) | Do not release keys or trust receipts from this workload; check which providers you trust (`--jwks`, `--mock-root`) |
| ENC2002 | broker, verifier | A verified workload does not satisfy the attestation policy: image, TEE, TCB, debug state, GPU, execution spec, policy or artifact differ; or development evidence meets a production policy or broker. A key broker's reply does not name the expected values; the broker logs them for its operator | Approve the new image or spec in a new policy, or refuse the workload |
| ENC2003 | broker | Attestation freshness: the challenge is unknown, expired or already used (a replay), or the evidence is stale, predates the challenge, or has expired | Request a new challenge and attest again |
| ENC2004 | broker, workload | Key release refused: no attested session, unknown asset, revoked key version, or a grant for another session. Also: the broker state fails authentication under the KEK (edited outside Encompute), is not authenticated (written by an earlier Encompute), or is kept in a store that cannot authenticate it; a workload with a hardware attester given an unpinned broker; a grant not signed by a broker key the workload's attested identity (its training spec) names; grants in one session signed by more than one broker key; with the spec's `asset_brokers`, a key it binds to no broker, or a grant naming another broker than the one it binds that key to | Attest first; rotate a revoked key; open grants only in their own session. Restore an edited state from a trusted backup; authenticate an earlier state with `encompute keys upgrade-state`. Take broker keys from the training spec, never from the job descriptor |
| ENC2101 | secure aggregation | A party is not in the aggregation spec, or a message is not signed by its party's identity key, or an attested round's contributor is unattested | Add the party to the consortium's parties.json (a new spec), or check the key it signs with |
| ENC2102 | secure aggregation | A contribution or round does not match the approved spec (PolicyID, ExecutionSpecID, shape, codec, parties or keys differ), belongs to another round, repeats a message, or replays an older round; a party's `--state` file is unreadable; a sequence outside 1 to 2^53−1 | Rebuild the spec from the same artifact and parties.json; start a new round |
| ENC2103 | secure aggregation | Too few parties remain (below the minimum or the protocol threshold): the round aborts and nothing is released | Rerun with more participants, or lower the minimum in a new policy |
| ENC2104 | secure aggregation | A protocol message is malformed, tampered, out of order, or the coordinator equivocated; or a reconstruction failed (a bad share) | Do not trust this round; rerun it and investigate the coordinator or party named |
| ENC2105 | compiler | The fixed-point encoding could overflow the modulus: parties × maximum code ≥ 2^modulus | Increase the modulus, or reduce the clip range or scale |
| ENC2106 | compiler | An aggregate declaration is invalid: not a sum of one input per party, a minimum outside 2..parties, a collusion bound the parties cannot meet, a bad codec, or an unknown output | Fix the declaration; tolerating more colluders needs more parties |
| ENC2201 | coordinator, owner, fine-tuning preview, control plane | RELEASE DENIED: the release would exceed an asset's privacy budget. For DP-SGD fine-tuning, the preview denies a run whose planned rounds would exceed it, before training. On the control plane, also a ledger frozen after a detected rollback (in the database or in the state anchor, whatever the database says): treated as exhausted | Stop releasing from this asset, plan fewer rounds, or have its owners approve a new budget (a new policy) |
| ENC2202 | coordinator, owner, control plane | A privacy ledger is malformed, tampered (deleted, reordered or edited entries), rolled back or reset, for another asset or policy, or not shown. On the control plane, `<STATE> STATE ROLLBACK`: the database no longer extends the state anchor. At startup (STARTUP REFUSED), STATE is PRIVACY, AUDIT, ANCHOR (the anchor is missing), FREEZE (a frozen ledger shown spendable), REVOCATION, SERVICE ACCOUNT, USER, JOB (a cancelled or failed job shown live), APPROVAL (a withdrawn approval held again), MEMBERSHIP (an organization listed again in a project it left), ROLE (a removed role held again), AUTHORIZATION (a revoked owner authorization shown unrevoked) or EXPIRY (an expired asset shown unexpired). While running (REFUSED), a spend on a rolled-back PRIVACY ledger or an AUDIT checkpoint over a rewound chain; neither is anchored | Restore the ledger; do not contribute until it extends the last checkpoint you saw. For the control plane: stop the service, then restore the missing entries or run `encompute-control recover` ([deployment.md](deployment.md)) |
| ENC2203 | compiler, secure aggregation | Privacy declarations are invalid (epsilon, delta, unit, clip, noise), or a budgeted asset is released without a privacy mechanism. A secure-aggregation aggregate is always a release, even when sealed: a budgeted asset in an aggregation without `dp` does not compile, and a party with a budget does not join such a round | Fix the declaration, or add `dp` (Python `privacy=`) to the aggregation |
| ENC2204 | runtime, control plane | A privacy mechanism, its parameters, randomness or receipt do not match the approved configuration (including non-production randomness). On the control plane, a reservation whose declared sensitivity is below what its own noise implies for the ledger's unit, or, in production, not drawn with `csprng` | Refuse the release; check the coordinator's privacy configuration and attestation |
| ENC2301 | trust graph | A piece of evidence (receipt, record, spec) is malformed or does not verify | Re-export it from its source; do not add evidence that fails verification |
| ENC2302 | trust graph | An owner authorization or revocation is missing, signed by a key that is not the owner's, for an asset the party does not own, expired or revoked; or a revocation of an authorization that another party signed | Have the asset's owner approve the program with `encompute trust authorize` |
| ENC2303 | trust graph | The trust bundle is inconsistent: a dangling edge, a node that contradicts its evidence, broken lineage, or an unsupported version | Rebuild the bundle from its evidence; do not edit `trust.json` by hand |
| ENC2401 | planner | PLANNING FAILED: no combination of available mechanisms satisfies every trust requirement (the report lists every candidate and why it was refused) | Make a mechanism available (a TEE with a key broker, an FHE backend, execution proofs), relax the policy explicitly, or restructure the program |
| ENC2402 | planner, trust graph, control plane, training worker | A confidential execution plan is invalid: a requirement dropped or not discharged, a mechanism unavailable or without its prerequisites, or a plan for another program or policy. Also a plan below the verifier's own floor (facts its compiler does not produce, development attestation or a research backend in production, a weaker profile than `--minimum-profile`); and, for DP-SGD training, a plan that is not the training spec's, or whose sampling rate is not the spec's (the Confidential Space worker reports PLAN MISMATCH) | Regenerate the plan with `encompute plan`; never edit a plan by hand |
| ENC2403 | aggregation, trust graph | Execution does not match the approved plan: another PlanId, no plan, or a round or execution without a planned mechanism | Run under the approved plan (`--plan`), or approve a new plan |
| ENC2501 | training | A training worker, model, dataset, layout or checkpoint does not match the approved training spec (another model version, dataset, code, LoRA configuration, plan or policy). Also: a spec whose model factory is not one the worker image ships, or whose arguments are outside its schema; a spec that names no key brokers; INPUT ADAPTER MISMATCH, a worker handed an adapter other than the spec's initial one (round 1) or the one the coordinator recorded for the previous round | Rebuild from the approved spec; a changed configuration needs a new spec and new approvals. Build models with `encompute.torch.models:tiny_classifier` or from a Hugging Face package |
| ENC2502 | training | A checkpoint or sealed artifact is corrupted, from another project or run, or behind the authoritative privacy ledgers (stale: a later round was released) | Resume from the latest checkpoint; never restore an older one |
| ENC2503 | training | EXPORT DENIED: a derived adapter inherits a release restriction from its base model, a dataset or an update | Keep the adapter inside the collaboration, or have every parent's owner permit public adapters |
| ENC2504 | model import, worker | MODEL PACKAGE REFUSED: a mutable revision, remote code (`*.py`, `auto_map`, `trust_remote_code`), pickled weights, an unknown file, a symbolic link, a `tokenizer_config.json` or `quantization_config` setting outside the allowlist, an unsupported architecture, or other library versions than the package binds | Import from an immutable commit with safetensors weights and a Transformers-native architecture; run the approved library versions |
| ENC2601 | control plane | Unauthenticated: no bearer token or service signature, an expired or forged token, a token from an untrusted issuer, a development token in production, a token without `iat`, issued in the future, not yet valid (`nbf`) or living longer than `ENCOMPUTE_MAX_TOKEN_LIFETIME_SECS`, or a disabled user. Also `GET /metrics` without the metrics token | Log in again (`encompute login`); in production use the configured OIDC provider. Ask an organization admin if your user was disabled |
| ENC2602 | control plane | Forbidden: the identity is a member of the organization but lacks the role for this action | Ask an organization admin for the role |
| ENC2603 | control plane | Not found: no such resource visible to this identity. Resources owned by other organizations are reported the same way, so their existence is not revealed | Check the ID, and that a collaboration grants your organization access |
| ENC2604 | control plane | Conflict: an invalid job state transition, an idempotency key reused with a different request, a revoked asset, a duplicate registration, or an approval of a governed authorization that is already approved, active or revoked (an approved authorization is immutable evidence: its approvals are closed) | Use a new idempotency key for a new request; revoked assets cannot be used; to change an approved authorization, propose a new one |
| ENC2605 | control plane, services, clients | Insecure configuration refused: production mode rejects development identities and tokens, development key stores, ephemeral databases, default credentials and secrets passed on the command line. `ENCOMPUTE_ENV` unset or misspelt. A client running a scheduled job with no evaluator key pinned, or with the unpinned opt-out under `ENCOMPUTE_ENV=production`. A SecAgg coordinator with a control plane whose `--control-asset` mapping is malformed or misses a budgeted asset | Configure the production equivalents (OIDC, a root key provider, PostgreSQL, secret files). Pin evaluator keys (`--trust-evaluator`, `ENCOMPUTE_TRUSTED_EVALUATORS`, `trusted_evaluators=`). Map every budgeted asset |
| ENC2606 | control plane | No registered, ready evaluator supports the job's backend and parameter profile | Register an evaluator with that capability, or wait for one to become ready |
| ENC2607 | services, clients | A service request or message is unsigned, signed by an unknown or disabled service, addressed to another recipient, expired, or replayed. A client refuses a job the control plane scheduled on an evaluator key not among the trusted evaluators (an empty set trusts none), before sending anything | Check the service identities and clocks; replays are refused by design. Check which evaluator keys you pinned |
| ENC2701 | control plane, key broker, governed projects | Missing owner authorization: a source of a governed project has no active owner-signed authorization, or an uploaded authorization signature does not verify against the organization's active governance key (wrong key, tampered body). A job in a governed project is refused with it when a source's owner (the submitter included) has not authorized the source for the job's purpose, or its program binds no registered source. At a governed key broker: the release names an authorization that is not installed there, or one of another organization; an authorization or revocation of another organization is not installed or applied | Have the owner sign the authorization body with its governance key (`encompute governance sign`) and upload the signature |
| ENC2702 | control plane, key broker, governed projects | Purpose mismatch: the purpose is not in the project, not active, not accepted by the authorizing organization, or differs from the one the authorization, job or program names. At a governed key broker: the installed authorization is for another project or purpose than the release | Propose, approve and accept the purpose first; use the purpose the owners authorized |
| ENC2703 | control plane, key broker, governed projects | Program not authorized: the program or program set differs from the one the owner authorized (never a wildcard). At a governed key broker: the execution runs a program, or a program under a confidentiality policy, the owner did not authorize, or its spec or binding is not the execution the workload attested | Ask the owner to authorize this exact program (or a program set containing it) |
| ENC2704 | control plane, key broker, governed projects | Asset version mismatch: an authorization names a dataset version the organization did not register, or a registered version's digest, series, version, owner, kind, parents or policy would change. At a governed key broker: the key is bound to no source version or to another one (a bound version never changes), the authorization is for another version, or the execution does not read the authorized version as its owner's source | Register a new version; versions are immutable |
| ENC2705 | control plane, key broker, governed projects | Authorization or purpose expired, or not yet valid: expiry is strict (`valid_from <= now < valid_until`, no margin). For a governed job also: its window (the earliest end of its authorizations, purpose and sources' deletion dates) ended before submission, scheduling or start, or a source expired (also at ticket issue). At a governed key broker the same strict window holds on its own clock, and the attestation must have been issued before the authorization ends | Issue a new authorization or purpose revision with a current window |
| ENC2706 | control plane, key broker, governed projects | Withdrawn, revoked or retired: the authorization was revoked, its purpose retired, or its dataset version revoked, at or before the time of use (a revocation is never retroactive: uses before it stay valid). At a governed key broker: the authorization was revoked there (by the owner's signed revocation, the owner's local act, or the control plane's deny-only notice), or the asset expired; a revoked authorization is never installed again | Issue a new authorization (revocation is never undone) |
| ENC2707 | control plane, governed projects | Four-eyes incomplete: the action needs distinct people of the approving organization (never a service account, an auditor, the proposer again, a governed job's own submitter, or a role held in another organization), with the roles the approval rule requires; a governed job whose authorization asks for per-job four eyes is not scheduled or started until every such owner's quorum has approved it | Have a different person with the required role approve |
| ENC2708 | control plane, trust graph, key broker, governed projects | Governance key revoked, not yet approved, or absent: the organization has no active governance key, or the key that signed was revoked at or before the time of use (or before the document's issue). An authorization signed by a revoked key is never used again, even after a new key is approved; uses before the revocation stay verifiable. At a governed key broker: no governance key is pinned, or an authorization or revocation is not signed by the pinned key | Register a governance key, have a different security admin approve it, and issue new authorizations signed with it |
| ENC2709 | compiler, control plane, key broker, governed projects | Release class or output form exceeded (on the control plane and in the compiler, reserved; enforced from the release-class phase). At a governed key broker: an output releases more, or to others, than the owner authorized | Release only what the class allows |
| ENC2710 | planner, control plane, key broker, governed projects | Residency or placement constraints unsatisfied (reserved; enforced from the residency phase). A key broker refuses to release keys for a governed execution that declares placement until attested placement can be verified | Choose an evaluator in an allowed location |
| ENC2711 | control plane, key broker, governed projects | Linkage policy mismatch (on the control plane, reserved; enforced from the linkage phase). At a governed key broker: the execution uses another linkage policy than the owner authorized | Use the linkage policy the owners authorized |
| ENC2712 | key broker, governed projects | Release ticket invalid, expired or replayed: missing where tickets are required, not signed by the pinned control-plane key, for another organization, broker, source version, evaluator, execution spec or authorization, not a key-release ticket, carrying a spec or binding its IDs do not name, outside its window (at most 300 seconds, with 60 seconds of clock skew counted against it), or already used at this broker | Request a new ticket for the scheduled job |
| ENC2713 | key broker | BROKER STATE ROLLBACK: the broker's state file is older than the generation mark in the organization's KMS, at the mark's generation with another MAC (a fork), one save ahead of it but not chained to the mark's MAC (a file from another history), more than one save ahead, not the state the operator expected (`--expect-generation`, `--expect-state-mac`) when the mark is first created, saved under a mark that is now missing, or opened without the mark it was saved under; or another copy of the state advanced the mark first. The broker does not start, or grants nothing. When the mark cannot be read or advanced (network, permissions), nothing is granted and the broker answers 503 | Restore the state file that was saved last, and make sure only one broker runs on it; configure its mark (`--generation-mark openbao --kv-mount MOUNT`); if the mark is unreachable, fix the KMS connection and retry |
| ENC2714 | key broker, governed projects | Authorization limit exhausted: the owner's authorization allows no more key releases (`max_releases`) or no more jobs (`max_executions`) at this broker. Releases are counted, and persisted, before a key is granted | Ask the owner for a new authorization |
| ENC2715 | control plane, key broker, governed projects | Key custody refused: in a governed project (always in sovereign custody) a source's key must be held by an active key broker its own organization registered. Registering an asset for such a project with no `key_ref`, with a platform broker, or with a broker the organization did not register (or disabled), or asking for a release ticket for a source held by one, is refused, and so is planning a program that reads such a source. A governed key broker refuses a release when the governance binding's per-asset broker map gives the key to another broker, or leaves it out. Registering a platform broker as an organization's own, or creating a governed project in standard custody, is refused too | Register a key-broker service account of your organization, have a security admin register it (`POST /v1/organizations/{id}/key-brokers`), and name it in the asset's `key_ref` |
